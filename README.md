# fluxnote

Локальный markdown-журнал с **собственным поисковым индексом**. Заметки — обычные `.md` файлы, которые можно править любым редактором; поверх них fluxnote держит инвертированный индекс и ранжирует выдачу по BM25. Ни сервера, ни СУБД, ни единой зависимости — только Node.js 20+.

```text
notes/*.md  ──tokenize──▶  inverted index  ──BM25──▶  ранжированный поиск
                (in-process, кэш по size+mtime в .fluxnote-index.json)
```

## Почему это не grep

`grep` перебирает файлы и ничего не знает про релевантность. Здесь:

- **Токенизация.** NFKC + нижний регистр; слова на латинице и кириллице, цифры, дефис и апостроф внутри слова. `ＮＧＩＮＸ`, `nginx` и `NGINX` — один термин.
- **BM25 (Okapi).** `k1 = 1.4`, `b = 0.75`: частота вхождения входит сублинейно, длинные заметки штрафуются, редкий термин весит больше частого.
- **Заголовок весит вдвое больше тела** — он индексируется дважды.
- **AND-семантика.** Все термины запроса должны встретиться в одной заметке; иначе результат пустой, а не «что-нибудь похожее».
- **Префиксное расширение.** Если точного термина нет, 4+ буквы разыскиваются как префикс (`поис` → `поиск`, `поиском`); `поис*` работает явно.
- **Инкрементальный reindex.** Файл перечитывается только если изменились `size` или `mtime`; правка в vim подхватывается без полной пересборки.

## Быстрый старт

```bash
npm install -g fluxnote           # или: git clone + npm link

fluxnote init
fluxnote new "Настройка nginx" прокси и кэш --tags infra,nginx
fluxnote new "Импорт" --stdin < note.md
fluxnote search nginx
fluxnote search "nginx кэш" --tag infra --json
fluxnote show 2026-10-14-настройка        # по префиксу или заголовку
fluxnote append 2026-10-14-настройка "upstream через socket"
fluxnote tag 2026-10-14-настройка important
fluxnote rm 2026-10-14-настройка --yes     # в .trash, не в пустоту
fluxnote stats
```

Хранилище по умолчанию — `~/.fluxnote` (переопределяется `--vault PATH` или `FLUXNOTE_HOME`):

```text
~/.fluxnote/
├── notes/2026-10-14-настройка-nginx.md
├── .trash/…            # корзина: rm не уничтожает данные
└── .fluxnote-index.json # кэш стадов, можно удалить — пересоберётся
```

## Формат заметки

```markdown
---
title: Настройка nginx
created: 2026-10-14T09:00:00.000Z
updated: 2026-10-14T11:36:49.019Z
tags: [infra, nginx]
---

# Запуск
proxy_pass 127.0.0.1:8080;
```

Frontmatter не обязателен: заметка, созданная руками без него, получает заголовок из первой markdown-строки. Незакрытый frontmatter — ошибка, а не тихий фолбэк. Файлы, начинающиеся с `.` или `_`, в индекс не попадают.

## Команды

| Команда | Назначение |
|---|---|
| `init` | создать хранилище |
| `new <заголовок> [слова…] [--tags a,b] [--stdin]` | добавить заметку |
| `search <запрос…> [--tag] [--since YYYY-MM-DD] [--limit N] [--json]` | BM25-поиск |
| `show <ref> [--json]` | полный текст |
| `list [--tag] [--limit] [--json]` | свежие заметки |
| `append <ref> <текст>` | дописать в конец тела |
| `tag <ref> <tag>` / `untag <ref> <tag>` | изменить теги |
| `rm <ref> --yes` | в корзину |
| `purge` | очистить корзину |
| `reindex` | пересобрать индекс с нуля |
| `stats [--json]` | размеры корпуса и частые термины |

`<ref>` — имя файла, префикс имени, подстрока имени или заголовок. Если ссылка неоднозначна, fluxnote перечислит варианты и ничего не тронет.

`search` без совпадений возвращает код `1` — удобно в скриптах. `show`/`rm` по несуществующей заметке тоже `1`, `неизвестная команда` — `2`.

## Модель поиска

```text
term ──normalize──▶ postings: term → { noteId → tf }
                    docs:     noteId → { dl, title, tags, body, updated }

score(note, query) = Σ_over_terms  idf(t) · tf·(k1+1) / (tf + k1·(1 − b + b·dl/avgdl))
idf(t)             = ln(1 + (N − df + 0.5) / (df + 0.5))
```

Результат — пересечение по всем терминам, сортировка по очкам, при равенстве — по свежести.

## Разработка

```bash
npm test          # node --test: 58 тестов — токенизация, BM25-свойства,
                  # frontmatter, инкрементальный reindex, CLI целиком
```

CI гоняет тесты на Node 20 и 22, Linux и Windows, плюс smoke-прогон CLI.

## Ограничения

- Индекс живёт в памяти процесса: на сотнях тысяч заметок придётся думать о персистентном индексе (здесь — только кэш стадов).
- Никакой стемминг-морфологии: `кэш` и `кэша` — разные термины, спасает только префикс от 4 символов.
- Нет синхронизации, шифрования и версий. Git для папки `notes/` — штатный способ получить всё три сразу.
- `rm` ведёт в `.trash`, но `purge` удаляет безвозвратно.
